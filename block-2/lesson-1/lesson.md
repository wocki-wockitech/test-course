# Go: основы языка и типы

Цель урока — закрыть базу по языку Go, которую почти всегда спрашивают на
собесе: чем slice отличается от array, как устроены map (и почему запись в
nil map паникует), интерфейсы и неявная реализация, value vs pointer
receivers, обработка ошибок как значений и `defer/panic/recover`. Простым
языком, с прицелом на устные ответы.

## Zero values: в Go нет «неинициализированных» переменных

Любая переменная без явного значения получает **zero value** своего типа:

- числа — `0`
- `string` — `""`
- `bool` — `false`
- указатели, срезы, map, каналы, функции, интерфейсы — `nil`

```go
var n int        // 0
var s string     // ""
var m map[string]int // nil
var p *int       // nil
```

> [!tip] Что сказать на собесе
> «В Go нет мусора в неинициализированных переменных — всегда zero value.
> Для слайсов и map zero value это `nil`, и с этим связаны типовые грабли.»

## Array vs Slice

**Array** — фиксированная длина, часть типа. `[3]int` и `[4]int` — разные
типы. Массив копируется целиком при присваивании и передаче в функцию.

**Slice** — это «окно» поверх массива: структура из трёх полей —
указатель на нижележащий массив, длина (`len`) и ёмкость (`cap`).

```go
a := [3]int{1, 2, 3}   // массив, копируется целиком
s := []int{1, 2, 3}    // слайс: ptr + len + cap
```

Когда передаёшь slice в функцию, копируется сам заголовок (три поля), но
он указывает на **тот же** массив — поэтому изменение элементов видно
снаружи.

### append и подводные камни

`append` добавляет элемент; если `cap` исчерпан, выделяется новый массив
большего размера и данные копируются. Если ёмкости хватает — элемент
пишется в существующий массив, и это может неожиданно затронуть другие
слайсы, смотрящие на тот же буфер.

```go
s := make([]int, 0, 4) // len=0, cap=4
s = append(s, 1, 2)    // тот же массив
```

> [!warning] Грабли
> Два слайса могут делить один массив. `append` без реаллокации меняет
> данные «соседа». Если нужна независимая копия — используй `copy` или
> `append([]T(nil), src...)`.

## Map: всегда инициализируй перед записью

Map — это хэш-таблица. **Запись в nil map вызывает panic**, а вот чтение
из nil map безопасно и возвращает zero value.

```go
var m map[string]int // nil
_ = m["key"]          // ок, вернёт 0
m["key"] = 1          // PANIC: assignment to entry in nil map
```

Правильно создавать через `make` или литерал:

```go
m := make(map[string]int)
m["key"] = 1 // ок
```

Доступ с проверкой наличия — «comma ok»:

```go
v, ok := m["key"] // ok == false, если ключа нет
```

> [!important] Частый вопрос
> Порядок обхода map **не определён** и намеренно рандомизирован. Никогда
> не полагайся на порядок итерации.

## Struct и receivers: value vs pointer

Методы можно объявлять с **value receiver** или **pointer receiver**.

```go
type Counter struct{ n int }

func (c Counter) GetValue() int { return c.n } // value receiver — работает с копией
func (c *Counter) Inc()         { c.n++ }      // pointer receiver — меняет оригинал
```

- **Value receiver** получает копию — изменения не видны снаружи.
- **Pointer receiver** работает с оригиналом — изменения сохраняются.

Правило выбора: бери pointer receiver, если метод меняет состояние, либо
структура большая (чтобы не копировать), либо нужна консистентность набора
методов. Не смешивай value и pointer receivers у одного типа без причины.

## Интерфейсы и неявная реализация

В Go интерфейсы реализуются **неявно**: нет ключевого слова `implements`.
Тип удовлетворяет интерфейсу, если у него есть все нужные методы.

```go
type Stringer interface {
    String() string
}

type User struct{ Name string }

func (u User) String() string { return u.Name } // User теперь Stringer — автоматически
```

Это даёт слабую связанность: интерфейсы можно объявлять рядом с
потребителем, а не с реализацией. Идиома Go — **маленькие интерфейсы**
(`io.Reader`, `io.Writer` — по одному методу).

### Пустой интерфейс и any

`interface{}` (с Go 1.18 — псевдоним `any`) удовлетворяется любым типом.
Чтобы достать конкретный тип, нужен type assertion или type switch.

```go
func describe(v any) string {
    switch x := v.(type) {
    case int:
        return "int"
    case string:
        return "string of len " + fmt.Sprint(len(x))
    default:
        return "unknown"
    }
}
```

> [!warning] nil interface != nil
> Интерфейс хранит пару (тип, значение). Интерфейс равен `nil`, только если
> и тип, и значение nil. Положив в `error` указатель-`nil` конкретного типа,
> получишь интерфейс, который `!= nil`. Это классическая ловушка.

## Ошибки как значения

В Go нет исключений для обычного потока. Ошибка — это обычное значение типа
`error` (интерфейс с методом `Error() string`), которое возвращают
последним результатом.

```go
f, err := os.Open("file.txt")
if err != nil {
    return fmt.Errorf("open config: %w", err) // оборачивание через %w
}
defer f.Close()
```

- `%w` в `fmt.Errorf` **оборачивает** ошибку, сохраняя цепочку.
- `errors.Is(err, target)` — проверяет, есть ли в цепочке конкретная ошибка
  (например `io.EOF`).
- `errors.As(err, &target)` — достаёт из цепочки ошибку нужного типа.

```go
if errors.Is(err, os.ErrNotExist) { /* файла нет */ }

var pathErr *os.PathError
if errors.As(err, &pathErr) { /* достали типизированную ошибку */ }
```

> [!tip] Что сказать на собесе
> «Ошибки в Go — это значения. Их явно прокидывают наверх, оборачивают через
> `%w`, а проверяют через `errors.Is`/`errors.As`, а не сравнением строк.»

## defer, panic, recover

`defer` откладывает вызов до выхода из функции. Несколько `defer`
выполняются в порядке **LIFO** (последний объявленный — первый выполненный).

```go
func demo() {
    defer fmt.Println("1")
    defer fmt.Println("2")
    defer fmt.Println("3")
}
// Вывод: 3 2 1
```

Аргументы `defer` вычисляются **в момент объявления**, а не вызова:

```go
i := 0
defer fmt.Println(i) // напечатает 0, даже если i изменится ниже
i = 10
```

`panic` разворачивает стек, выполняя отложенные `defer`. `recover`,
вызванный внутри `defer`, перехватывает панику и возвращает выполнение в
нормальное русло.

```go
func safe() (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("recovered: %v", r)
        }
    }()
    panic("boom")
}
```

> [!important] Идиома
> Паника — для действительно исключительных ситуаций (баг программиста),
> а не для ожидаемых ошибок. Ожидаемое — возвращаем как `error`.

## Итог

- В Go всегда zero value; для slice/map/указателей это `nil`.
- Array копируется целиком; slice — это заголовок (ptr+len+cap) над массивом.
- Запись в nil map → panic; чтение безопасно. Всегда `make` перед записью.
- Интерфейсы реализуются неявно; идиома — маленькие интерфейсы.
- Ошибки — значения: оборачиваем `%w`, проверяем `errors.Is`/`errors.As`.
- `defer` — LIFO, аргументы вычисляются при объявлении; `recover` только в defer.
